# Original 2.48.32 runtime comparisons

The CLI prepares controlled native `.sim` files, advances the Rust engine from the same file, and compares saves produced by the two programs. An original save is the oracle. No expected state generated by Rust counts as original runtime evidence.

Run these commands only after the implementation batch is finished and the CLI is built. Use a new evidence directory for each qualified Git commit. Every output uses exclusive creation so existing inputs, user saves and oracle receipts remain intact.

```powershell
.\target\release\darwinbots-cli.exe native-suite --directory D:\Darwinbots-Oracle\qualified-commit
.\target\release\darwinbots-cli.exe native-replay --simulation D:\Darwinbots-Oracle\qualified-commit\movement-start.sim --until-cycle 10 --output-sim D:\Darwinbots-Oracle\qualified-commit\movement-rust-cycle10.sim
.\target\release\darwinbots-cli.exe native-compare --left D:\Darwinbots-Oracle\qualified-commit\movement-original-cycle10.sim --right D:\Darwinbots-Oracle\qualified-commit\movement-rust-cycle10.sim
```

For an interchange check before advancing the world, use `native-replay --ticks 0` and compare its output against the original input with `--absolute-tolerance 0 --relative-tolerance 0`. This checks the compared saved fields at the existing cycle.

For each case, load the start file in the isolated original `Darwin2.48.32.exe`, advance to the exact requested cycle, pause, and save under a new `*-original-cycleN.sim` filename. Retain executable SHA256, Git commit, start-file SHA256, saved-file SHA256 and observed cycle in the receipt. The comparison checks the saved cycle too; saving at a nearby cycle cannot pass. Use the original single-cycle control for the first checkpoint. Start each later comparison from the same initial file. Do not overwrite the user's `test.sim` or alter registry/OCX setup.

The manifest contains movement, fixing, contact separation, body conversion, ties, feeding and reproduction cases at cycles 1, 10 and 100. Brownian motion and gene mutation are disabled. Feeding and reproduction still consume random draws, so they are marked as random sensitive. Expand deterministic mechanics first and record each mismatch as a repair target. Do not suppress unexpected fields by increasing tolerances globally.

The JSON report compares live robot scalar fields, every DNA and memory word, mutation rates, skin, epigenetic staging, decoded tie parameters and active shot slots. Robots are matched by absolute identity, and tie/shot owner pointers are mapped from saved slots. Integer fields are exact. Float tolerance defaults to `1e-4 + 1e-6 * max(abs(left), abs(right))`; use zero tolerances when bit equality is required. Differences return a failing exit status even when output is capped. Private display definitions, ancestry, logs, graph series and GUI state require their own checks. Active shots are matched by saved slot.

Original `.sim` files omit the global VB6 Rnd and Gaussian spare. Loading the same save into both programs does not establish equal random continuation. Deterministic case results only establish equality for their compared fields and cycles. Random trajectory claims require independently captured original RNG state or repeated distributional evidence. The tool prints this limitation in every report.
